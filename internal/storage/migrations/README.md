# Database Migrations

This directory contains database migration files using [golang-migrate](https://github.com/golang-migrate/migrate).

## Migration Files

Migration files follow the naming convention: `{version}_{description}.{direction}.sql`

- `{version}` - Sequential migration number (e.g., 000001, 000002)
- `{description}` - Brief description of the migration
- `{direction}` - Either `up` (applies migration) or `down` (rolls back migration)

## Current Migrations

1. **000001_create_users_table** - Creates the users table with IDENTITY column
2. **000002_create_entries_table** - Creates the entries table with indexes and IDENTITY column

## Database Design Notes

- **IDENTITY columns**: We use `GENERATED BY DEFAULT AS IDENTITY` instead of `SERIAL` for better SQL standard compliance and integrated sequence management. See [PostgreSQL SERIAL vs IDENTITY](https://stackoverflow.com/questions/55300370/postgresql-serial-vs-identity) for more details.

## Running Migrations

Migrations are automatically run when the application starts via `NewDB()`.

To manually run migrations, you can use the `migrate` CLI tool:

```bash
# Install migrate CLI
brew install migrate  # macOS
# or download from https://github.com/golang-migrate/migrate/releases

# Run migrations
migrate -path ./internal/storage/migrations -database "postgres://user:password@localhost/gophkeeper?sslmode=disable" up

# Rollback last migration
migrate -path ./internal/storage/migrations -database "postgres://user:password@localhost/gophkeeper?sslmode=disable" down 1
```

## Adding New Migrations

1. Create new migration files:
   - `{next_version}_{description}.up.sql` - Forward migration
   - `{next_version}_{description}.down.sql` - Rollback migration

2. Migrations are embedded into the binary at build time using Go's `embed` package.
